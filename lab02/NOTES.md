# Конспект по Git

## Рабочая папка, индекс и коммит

**Рабочая папка (working directory)** — это набор файлов на диске,
которые я вижу и редактирую. Git отслеживает их изменения, но пока
не сохраняет в историю.

**Индекс (staging area)** — промежуточная область, куда я добавляю
изменения командой `git add`. Это «черновик» будущего коммита:
в индекс можно положить не все изменения, а только нужные.

**Коммит (commit)** — зафиксированный снимок состояния индекса
в истории репозитория. У коммита есть хеш, автор, дата и сообщение.
После коммита изменения попадают в историю и на них можно ссылаться.

## Git и GitHub — в чём разница

**Git** — распределённая система контроля версий, работающая локально.
**GitHub** — облачный сервис для хранения Git-репозиториев.

## Использованные команды

- `git status` — показывает текущее состояние: какие файлы изменены,
  какие в индексе, какие не отслеживаются, на какой ветке я нахожусь.
- `git diff` — сравнивает рабочую папку с индексом: что изменено,
  но ещё не подготовлено к коммиту.
- `git diff --staged` — сравнивает индекс с последним коммитом:
  что именно попадёт в следующий коммит.

  ## Ветки

**Ветка (branch)** — это подвижный указатель на коммит. Она позволяет
вести параллельную линию разработки, не затрагивая основную.

При **новом коммите** указатель текущей ветки автоматически
передвигается на этот коммит. Другие ветки остаются на своих местах.

**Слияние (merge)** — объединение изменений одной ветки в другую.
При слиянии создаётся новый коммит (или выполняется fast-forward),
в котором соединяются истории обеих веток.
